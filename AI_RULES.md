# AI Rules For `achievement_collections_REACT`

Этот файл хранит правила работы по проекту. Его нужно обновлять, если меняются процесс, критерии завершения, ограничения по изменениям или обязательные проверки.

## 1. Базовые правила

1. Общаться на русском языке.
2. Перед любой новой задачей сначала сверяться с `Plan.md`.
3. Если проблема уже запланирована в `Plan.md`, не подавать её как новую незапланированную проблему.
4. Работать по шагам и подпунктам плана, по одному подпункту за раз.
5. Если есть замечания к плану или лучшее решение, сначала обсудить это, а не молча менять направление.

## 2. Минимальность изменений

1. Не делать крупные рефакторы без отдельного согласования.
2. Не менять архитектурные слои, backend flow, naming conventions или организацию папок без явного подтверждения.
3. Предпочитать минимальные изменения, совместимые с текущей архитектурой.
4. Не изменять существующий working code без необходимости для текущей задачи.
5. Не трогать соседний код "заодно", если для этого нет конкретной технической причины.
6. Не предлагать рефакторы, оптимизации или исправления без конкретной технической причины, бага, риска или требования плана.
7. Не чинить то, что не сломано.

## 3. Анализ перед кодом

Перед изменением нескольких файлов или перед структурной правкой:
1. коротко описать план;
2. перечислить файлы, которые планируется менять;
3. если изменение крупное, архитектурное, затрагивает shared-контракты, роутинг, dev-инфраструктуру, удаление/переименование или много связанного кода, дождаться подтверждения.

Для мелких локальных правок без нетривиальных последствий отдельная остановка не нужна.

## 4. Документация и контекст

1. После каждой правки кода обновлять `Docs`, если изменены файлы из покрываемых директорий.
2. После каждой правки запускать `npm.cmd run docs:check`.
3. Если изменилось текущее состояние проекта, принятые решения, маршруты, API, dev-схема, важные команды, текущий этап плана или рабочие договоренности, обновлять `CHAT_CONTEXT_PROMPT.md`.
4. Если изменились правила работы, критерии завершения или процесс выполнения задач, обновлять `AI_RULES.md`.
5. После выполнения задачи явно сообщать, что документация и контекст синхронизированы.

## 5. Проверки

Базовые проверки после содержательных изменений:
- `npm.cmd run docs:check`
- `npx.cmd tsc -b`
- `npm.cmd run lint`

Если затронута логика, UI-сценарии, роутинг, API или поведение:
- по возможности запускать `npm.cmd run test`

Если какая-то проверка не запускалась, нужно прямо сказать об этом и почему.

## 6. Definition of Done

Задача считается завершённой только если:
- реализована цель задачи;
- код работает;
- `Docs` обновлены;
- `docs:check` проходит;
- `lint` проходит;
- `TypeScript check` проходит;
- если задача затрагивает поведение, прогнаны релевантные тесты или явно сказано, почему не прогнаны;
- existing flow не сломан;
- дан краткий отчёт по изменениям с перечислением файлов и выполненных проверок.

## 7. Runtime Constraints

- Windows environment
- PowerShell execution policy limitations
- prefer `npm.cmd` over bare `npm`
- `vercel dev` unreliable locally
- локальная схема разработки:
  - `npm.cmd run dev` для frontend
  - `npm.cmd run dev:api` для backend
- avoid solutions depending on WSL unless explicitly requested
- если CLI-проверка проходит, а VS Code показывает старую ошибку, сначала проверить, не это ли stale editor cache
- если backend не стартует, сначала проверить, не занят ли порт `3000` старым процессом

## 8. Формат отчёта после задачи

После выполнения задачи сообщать:
- какие файлы изменены;
- что именно изменено по сути;
- какие проверки запускались;
- что не удалось проверить, если такое было.
