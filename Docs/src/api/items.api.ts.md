# src/api/items.api.ts

## Что делает файл

Файл содержит клиентский API-вызов для защищенного endpoint `/api/items`.
Текущая задача модуля - выполнить smoke-проверку: получить ID-токен и отправить тестовый запрос с Bearer авторизацией.

## Импорты и зависимости

1. `src/firebase.ts` (`getIdToken`) - получение токена текущего пользователя для авторизованного запроса.

## Экспорты и контракты

1. Экспортируется интерфейс `ProtectedProbeResult`:
2. `ok`, `status`, `data`.
3. Экспортируется функция `probeItemsEndpoint(): Promise<ProtectedProbeResult>`.
4. Функция не принимает аргументы.
5. Инварианты:
6. Если токен отсутствует, функция бросает ошибку до сетевого запроса.
7. В заголовке `Authorization` всегда отправляется `Bearer <token>`.
8. Даже при не-JSON ответе функция не падает на parse: `data` будет `null`.

## Нетривиальная логика

1. Проверка токена перед fetch дает ранний и понятный фейл для неавторизованного состояния.
2. `response.json().catch(() => null)` защищает от runtime-ошибки, если сервер вернул пустое тело или не-JSON.
3. Функция возвращает унифицированную структуру, чтобы вызывающий код сам решал, считать ли `!ok` ошибкой или предупреждением.

## Где используется

1. `src/store/auth.store.ts` - метод `probeProtectedApi` вызывает `probeItemsEndpoint` после login/register.
2. Косвенно участвует в формах:
3. `src/components/Auth/LoginForm.tsx`.
4. `src/components/Auth/RegisterForm.tsx`.
