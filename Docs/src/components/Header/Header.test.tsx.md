# src/components/Header/Header.test.tsx

## Что делает файл

Файл проверяет поведение компонента Header в трех ключевых состояниях:

1. Идет проверка auth-сессии (loading/skeleton).
2. Гость (публичная навигация + кнопки входа/регистрации).
3. Авторизованный пользователь (приватная навигация + приветствие).

## Импорты и зависимости

1. `vitest` (`describe`, `it`, `expect`, `vi`) - структура тестов и мокирование.
2. `@testing-library/react` (`render`, `screen`) - рендер компонента и assertions по DOM.
3. `react-router-dom` (`MemoryRouter`) - тестовый роутер для работы `Link` внутри Header.
4. `./Header` - тестируемый компонент.
5. Мок `../ThemeToggle/ThemeToggle` - упрощает тесты, чтобы изолировать сценарии навигации/auth от темы.

## Экспорты и контракты

1. Экспортов нет.
2. Внутренняя helper-функция `renderHeader(props?)`:
3. Рендерит `Header` в `MemoryRouter` и позволяет передавать частичные пропсы Header через `Partial<Parameters<typeof Header>[0]>`.
4. Проверяемый контракт Header в тестах:
5. При `isAuthResolving=true` не показывать гостевые кнопки.
6. Для гостя показывать `Примеры коллекций` и кнопки auth.
7. Для авторизованного - показывать приветствие и скрывать как гостевые пункты, так и дублирующую private-ссылку `Мои коллекции`.

## Нетривиальная логика

1. Компонент зависит от router-контекста, поэтому `MemoryRouter` обязателен в тестовом рендере.
2. Проверка `getAllByText(...).length > 0` используется из-за наличия desktop/mobile версий элементов в одном рендере.
3. Мок ThemeToggle делает тесты стабильнее и быстрее, убирая лишнюю зависимость от анимаций/логики темы.

## Где используется

1. Запускается Vitest через `npm run test`.
2. Тестирует `src/components/Header/Header.tsx`.
3. Подключает общий test setup из `src/test/setup.ts` через конфиг `vite.config.ts` (`test.setupFiles`).
