# src/components/Auth/LoginForm.tsx

## Что делает файл

Компонент реализует форму входа пользователя по email и паролю.
Форма валидирует поля на клиенте, вызывает `login` из auth-store и сообщает контейнеру об успешной авторизации через `onSuccess`.

## Импорты и зависимости

1. `react-hook-form` (`useForm`) управляет состоянием формы, валидацией и submit.
2. `src/store/auth.store.ts` (`useAuthStore`) даёт `login`, `error` и `clearError`.

## Экспорты и контракты

1. Экспортируется default-компонент `LoginForm`.
2. Проп `onSuccess: () => void` вызывается после успешного login.
3. Проп `onSwitchToRegister: () => void` переключает модалку на форму регистрации.
4. Локальная форма `LoginFormValues` содержит `email` и `password`.
5. Инварианты:
5.1. `login(email, password)` вызывается только после успешной клиентской валидации.
5.2. Ошибка авторизации читается только из `auth.store.error` и рендерится внутри формы.

## Нетривиальная логика

1. Перед submit форма всегда вызывает `clearError()`, чтобы убрать старое сообщение об ошибке от предыдущей попытки.
2. Блок `catch` после `login` намеренно пустой, потому что текст ошибки уже записан в `auth.store`, а модалку нужно просто оставить открытой.
3. При переключении на регистрацию компонент сначала очищает ошибку, потом вызывает `onSwitchToRegister`.
4. Валидация:
4.1. `email` проверяется на обязательность и формат.
4.2. `password` проверяется на обязательность и минимальную длину 6 символов.

## Где используется

1. `src/components/Auth/AuthModal.tsx` - рендер формы в login-режиме.
2. `src/components/Auth/LoginForm.test.tsx` - тестирует клиентскую валидацию, submit и показ ошибок.
3. `src/components/Auth/AuthModal.test.tsx` - мокает компонент для изоляции контейнерной логики модалки.
