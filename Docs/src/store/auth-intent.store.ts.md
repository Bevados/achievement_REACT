# src/store/auth-intent.store.ts

## Что делает файл

Файл хранит отдельный Zustand-store для отложенного пользовательского намерения после авторизации.
В текущем шаге используется intent `create-collection`, который ставится из Hero CTA на гостевой главной.

## Импорты и зависимости

1. `zustand` (`create`) - создание локального UI-store без серверных зависимостей.

## Экспорты и контракты

1. Экспортируется тип `AuthIntent`.
2. `AuthIntent` сейчас поддерживает два значения: `create-collection` и `null`.
3. Экспортируется хук-store `useAuthIntentStore`.
4. Контракт store:
5. `pendingIntent` - текущее отложенное действие.
6. `setIntent(intent)` - устанавливает новое намерение.
7. `consumeIntent()` - возвращает текущее намерение и сразу очищает его.
8. `clearIntent()` - очищает намерение без чтения.

## Нетривиальная логика

1. Метод `consumeIntent` реализован атомарно на уровне store-операции: сначала читает текущее значение из `get()`, затем сбрасывает `pendingIntent` в `null`.
2. Это предотвращает повторное исполнение одного и того же намерения при повторном рендере.

## Где используется

1. `src/App.tsx` - устанавливает intent из Hero CTA и очищает его для обычного login/register из Header.
2. В следующих шагах будет подключен consumer intent в private-flow создания коллекции.
3. Контракт покрыт тестами в `src/store/auth-intent.store.test.ts`.
