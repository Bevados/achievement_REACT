# Docs: правила проектной документации

Папка Docs зеркалирует структуру исходников для директорий src, api и lib.

## Маппинг путей

- Исходник: src/components/Header/Header.tsx
- Док-файл: Docs/src/components/Header/Header.tsx.md

## Когда обновлять документацию

1. При любом изменении файла в src, api, lib.
2. При изменении публичного контракта (типов, API, входов/выходов функций, бизнес-правил).
3. При переносе логики между файлами.

## Обязательные разделы в каждом doc-файле

1. Что делает файл
2. Импорты и зависимости
3. Экспорты и контракты
4. Нетривиальная логика
5. Где используется

## Команды

1. npm run docs:scaffold

- Опционально: создает недостающие doc-файлы по шаблону.
- Используй в двух случаях: первый запуск процесса Docs и массовое добавление новых файлов в src/api/lib.

2. npm run docs:check

- Проверяет, что измененные source-файлы сопровождаются изменениями в Docs.
- Проверяет наличие обязательных разделов в измененных doc-файлах.

## Рекомендуемый процесс работы

1. Меняешь код в src/api/lib.
2. Сразу в этой же задаче обновляешь соответствующий файл в Docs.
3. Запускаешь npm run docs:check.
4. Если checker прошел, значит файл документации есть и обновлен вместе с кодом.
