# lib/validation/item.schema.ts

## Что делает файл

Файл хранит Zod-схемы для валидации данных `items` на уровне API.
Схемы используются контроллером до вызова сервиса, чтобы в бизнес-слой попадали только корректные данные.

## Импорты и зависимости

1. `zod` (`z`) - библиотека runtime-валидации.
2. `../types/item.types` - типы DTO для строгой связи между TypeScript-контрактом и runtime-схемой.

## Экспорты и контракты

1. `createItemSchema` - валидация тела запроса для создания item.
2. `updateItemSchema` - валидация тела PATCH (все поля опциональные).
3. `itemIdSchema` - валидация id в формате 24-символьной hex-строки.
4. Инварианты:
5. Для create поле `name` не может быть пустым.
6. Для update все поля optional, чтобы поддерживать частичное обновление.
7. id для операций update/delete должен соответствовать формату ObjectId.

## Нетривиальная логика

1. Использование `z.ZodType<CreateItemDto>` и `z.ZodType<UpdateItemDto>` связывает runtime-валидацию с TS-типами и снижает риск расхождения контрактов.
2. `itemIdSchema` валидирует именно строковый формат id; фактическое существование документа в БД проверяется позже в сервисе/репозитории.
3. Ошибки этой схемы обрабатываются в контроллере и преобразуются в JSON-ответ для клиента.

## Где используется

1. Прямое использование в `lib/controllers/item.controller.ts`:
2. `createItemSchema` в `createItem`.
3. `updateItemSchema` в `updateItem`.
4. `itemIdSchema` в helper `getIdFromQuery` для `updateItem` и `deleteItem`.
5. Косвенно влияет на клиентскую обработку ошибок при запросах к `api/items` через `src/api/items.api.ts`.
